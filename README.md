# z-harness

Worktree isolation and a plan gate for Claude Code sessions, packaged as a plugin.

Extracted from a production repository where every guard in here was written after the bug it now
catches. It carries the mechanisms, not that project's rules: what counts as a sensitive path is
declared by the repository you install it into.

Requires `git`, `bash`, and `jq`.

## What it does

**Worktree isolation** (`auto-worktree.sh`, `PreToolUse`). Refuses file edits made outside a git
worktree, so a session's work lands on a branch instead of on the main working tree. Writes to
`/tmp`, to build output (`dist/`, `node_modules/`, `obj/`), and to paths outside the repository are
allowed without one.

It refuses shell commands that write, not only the `Edit` and `Write` tools. A guard that reads tool
payloads and ignores `cat > file <<EOF` will watch a heredoc perform the change it just declined.
The detector skips heredoc bodies and quoted text, so `grep -rn 'tee -a' .` is not mistaken for a
write — this is a syntax guard, not a sandbox, and `sh -c "cat > x"` gets through.

It also refuses an `npm ci` that would delete a `node_modules` symlinked out of the tree the command
runs in. Keyed on the symlink rather than on "am I in a worktree", so `npm ci` in the main tree stays
allowed and `npm ci --prefix <worktree>/app` from anywhere is still caught.

**Plan gate** (`require-plan.sh`, `PreToolUse`). Blocks the first edit into a path the repository
calls sensitive until the session has written `.claude/state/plan-<session>.md` — at least three
lines saying what changes, what it sits near, and how it will be verified. `.claude/` itself is
always in the gated set: editing a hook cannot break your invariants, but it can quietly remove the
check that would have caught something that does.

**Decision log** (`lib-hook-log.sh`). Every hook decision, `allow` as well as `block`, appended as
JSONL to `$(git rev-parse --git-common-dir)/z-harness-hooks.jsonl` — inside the git directory,
never in a working tree, because a log file in the tree makes every worktree dirty and every merge
refuse. Paths and reason codes only, never file contents.

```bash
jq -s 'group_by(.reason) | map({(.[0].reason): length}) | add' \
  "$(git rev-parse --git-common-dir)/z-harness-hooks.jsonl"
```

Logging the allows is the point. Without a denominator, a false-refusal rate is not computable, and
the write detector in here had its patterns tuned twice by guesswork for exactly that reason.

**Content rules** (`check-content-rules.sh`, `PreToolUse`). Compares the text a call is about to
write against rules the repository declared, and refuses the write when one is broken. See
[Content rules](#content-rules).

**Conventions** (`check-conventions.sh`, `PostToolUse`). Reads the file the session just wrote and
reports what the repository's own rules say is missing: a doc comment on every declaration, and no
line matching a pattern the repository forbids. Runs after the write, so nothing is undone — the
finding just reaches the model while the file is still what it is working on, rather than at the end
of the session when the context that made writing it cheap is gone.

Entirely opt-in. With no `conventions` block in `.claude/harness.json` it reads nothing:

```json
{
  "conventions": {
    "docComments": true,
    "skip": ["/generated/"],
    "generatedBanners": ["auto-generated by openapi-typescript"],
    "forbiddenText": { "pattern": "[\u00e0\u00e1\u1ea3\u00e3\u1ea1\u0111]", "label": "non-English text in code" }
  }
}
```

`docComments` covers `.cs` (`///`), `.ts` and `.tsx` (`/** */`), and never applies inside `test/` or
`tests/` — a test name there is already a sentence and a comment above it would only restate it.
`generatedBanners` exempts a file by what its first ten lines say rather than by where it sits:
naming paths is how the upstream version failed, when the same generator wrote a second file nobody
had added to the list.

**Gate before stop** (`verify-before-stop.sh`, `Stop`). Works out what the session changed, runs the
gates that cover it, and blocks the stop while any of them is red. Then merges the worktree branch —
fast-forward only, and only once the gates are green. See [Gates](#gates).

**Merge helper** (`merge-worktree.sh`). The merge itself, also runnable by hand from anywhere:

```bash
bash <plugin>/hooks/merge-worktree.sh <worktree path>
```

Fast-forward only, so a branch that has fallen behind is refused with the rebase to run rather than
merged. Refuses a dirty worktree, and a main working tree with uncommitted changes to tracked files —
untracked files there do not block it.

## Install

From a local directory, which is enough to try it and needs no remote:

```
/plugin marketplace add /absolute/path/to/z-harness
/plugin install z-harness@z-harness
```

## Configure the repository

Create `.claude/harness.json` in the repository you installed it into:

```json
{
  "sensitivePaths": [
    "^src/billing/",
    "^migrations/"
  ]
}
```

Extended regular expressions, matched against repository-relative paths. With no file, or an empty
list, the plan gate covers `.claude/` and nothing else — it never falls back to gating everything.

Add to that repository's `.gitignore`:

```
.claude/worktrees/
.claude/state/
```

Both matter, though not for the reason an earlier version of this file gave. The merge's cleanliness
check reads `--untracked-files=no`, so an un-ignored `.claude/worktrees/` does not refuse the merge —
tested, after the claim that it did turned out to be false. What it does do is put every worktree's
files in reach of `git add -A` in the main tree, and fill `git status` with them.

## Tell the model the workflow

The hooks enforce a workflow; they do not explain it. Without the prose, a session gets blocked by a
rule nobody wrote down. Paste this into the repository's `CLAUDE.md`:

```markdown
## Worktree isolation — edit in a worktree, not on main

Every file edit must happen inside a git worktree. The main working tree is for setup
(dependency installs, docker compose) and read-only work.

1. **Setup** (main tree): install dependencies, start services. Bash and Read are allowed here;
   only Edit/Write are blocked.
2. **Edit** (worktree): call `EnterWorktree` with a descriptive name. The worktree is created at
   `.claude/worktrees/{name}` on branch `worktree-{name}`.
3. **Commit inside the worktree** before finishing. A dirty worktree cannot be merged, so an
   uncommitted change means the work stays on the branch.
4. **Merging is automatic** once the gates pass — do not merge by hand, and never with
   `git update-ref`: that moves the pointer without touching the main tree's index, so main
   immediately reports the whole merge as staged changes in reverse.

If the merge is refused because the branch has diverged, `git rebase main` inside the worktree and
stop again. If you are told the merge is still failing, the work is on the branch and nowhere else —
say so, name the branch, and do not report the task as merged.

Editing any path listed in `.claude/harness.json`, or anything under `.claude/`, requires a plan
at `.claude/state/plan-<session>.md` first — at least three lines: what changes, what it sits
near, how it will be verified.
```

## The progress-reader agent

Ships with the plugin, read-only, and answers one question in at most twenty lines: *where does this
project stand on X, and what is in the way*. Use it at the start of a session instead of reading a
handoff file end to end.

It finds the files itself, but tell it where to look and it stops guessing:

```json
{
  "stateDocs": {
    "state":     "docs/PROGRESS.md",
    "runbook":   "docs/ops-runbook.md",
    "decisions": "docs/IMPLEMENTATION-PLAN.md",
    "avoid":     ["docs/briefs/", "docs/architecture.md"]
  }
}
```

With no `stateDocs`, it looks for the conventional names — `PROGRESS.md`, `STATUS.md`, `TODO.md`,
`RUNBOOK.md` and their `docs/` variants — and says which one it used. A caller who believes it read
the handoff file when it actually read a stale TODO believes the wrong thing about their own project.

The rule it will not break: it never infers a status from the presence of code. "The endpoint exists"
is not "the task is done"; when the status table and the code disagree, it reports the disagreement
rather than picking a side.

## Content rules

The mechanism a repository states its own invariants through. None of the rules ship with the
plugin — it supplies the reading, never the rule:

```json
{
  "contentRules": [
    { "match": "^src/edge/",
      "forbid": "Cache-Control:[^\"]*immutable",
      "why": "HTML must never be immutable; a browser cannot purge it." },
    { "match": "^src/edge/robots\\.ts$",
      "require": "X-Robots-Tag",
      "why": "The default subdomain must stay noindex." }
  ]
}
```

`match` is an extended regular expression over the repository-relative path, with any worktree prefix
stripped — every edit happens in a worktree, so without that strip no rule would ever match anything.

`forbid` refuses when the text being written matches it. `require` refuses when the text being
*replaced* matched and the replacement does not: it catches removal, not absence. That distinction is
the reason this hook reads `old_string` at all. Every check phrased as "what does the new text say"
is blind to a deletion, because deleting produces no new text — and that was the one edit shape that
could remove a guarantee upstream without any rule seeing it.

**Shell commands that write a ruled path are refused, not inspected.** A redirect does not carry its
bytes anywhere the hook can read them, and a check that cannot run must not report that it passed —
upstream, a heredoc walked straight past the rule that had just refused the identical change as an
Edit. The refusal says to use Edit or Write instead.

**Declared mutation.** Writing `.claude/state/mutation-<session>.md` with at least one line of reason
lets that session's writes through for thirty minutes, logged under its own reason code rather than
as an ordinary allow. It exists because a rule and the test proving that rule is still alive point at
each other: breaking a rule on purpose is how you find out the test still catches it, and without a
door that is the one thing the rule makes impossible. The window expires on its own, an empty file
does not count, and it belongs to one session.

## Gates

`verify-before-stop.sh` is a frame with no commands of its own. What runs comes from
`.claude/harness.json`:

```json
{
  "gates": {
    "router": { "match": "^apps/router/",                  "dir": "apps/router", "run": ["npm run lint", "npm test"] },
    "web":    { "match": "^(apps/web/|packages/core/)",    "dir": "apps/web",    "run": ["npm run build", "npm test"] }
  },
  "reviewReceipt": { "agent": "invariant-reviewer" }
}
```

Gates run in the order written, and only when `match` — an extended regular expression — hits one of
the changed paths. A shared package that two applications import belongs in both patterns; a change
to it should run both. A gate's commands run in `dir` in order and stop at the first failure, so a
suite that could not build is not also reported as failing its tests. Passing gates are silent.

The changed set is the uncommitted files, and in a worktree the whole branch as well. That second
half matters: judged by uncommitted files alone, committing — the step that makes the merge possible
— is what makes every gate skip.

A command can say something without failing:

```
### NOTE integration tests skipped
```

printed on stdout is surfaced to the model and does not block the stop. A missing local Docker daemon
is not a broken gate, and treating it as one blocks every stop on that machine until someone deletes
the hook. `### FAIL <name>` is accepted the same way, for a command that reports several results in
one run.

**Budgets.** Red gates block at most three stops, then the stop is allowed through with a message in
capitals saying nothing was verified. A guard that can trap a session in a loop gets removed rather
than fixed. A failing merge has the *same* budget on a *separate* counter — sharing one means two
unrelated failures spend the same budget, and since a green gate clears the gate counter, a shared
counter never counts at all and a session that cannot merge can never stop.

**`reviewReceipt`** (optional). When a change touches a path in `sensitivePaths`, the stop is blocked
until `.claude/state/review-<HEAD sha>.json` exists, and the message names the agent to run. It is
the answer to rules no hook can read out of a diff — write order, where a value came from, whether an
operation is idempotent. A gate that cannot observe its own condition must not block, so the receipt
is what makes the condition observable. Keyed to HEAD, so committing again invalidates it: that is a
different diff. Stated limit — an agent that writes the file without reading anything passes. This
guards against forgetting, not against intent.

## Tests

```bash
bash tests/test-hooks.sh
```

Three classes of case, and skipping any of them has cost this code before:

1. **Executable check** — the hook list is read out of `plugin.json` and every entry must exist and
   carry the execute bit. A hook invoked by a bare path without that bit fails silently, and a silent
   failure is indistinguishable from a decision to allow. One guard upstream lived its entire life
   that way, blocking nothing; the evidence was negative — no log line ever named it.
2. **False refusal** — every blocking rule also has a case proving it has not opened too wide. This
   half costs more to write than the blocking half, and dropping it is the fastest route to a guard
   being deleted by the person it keeps interrupting.
3. **Behaviour** — configuration plumbing, and the worktree-prefix strip that every check depends on.
   Without that strip, every check silently misses every edit, since every edit happens in a worktree.

The suite is mutation-tested: removing an execute bit, or widening the sensitive-path regex to match
everything, both turn it red.
